## Evidence policy and acknowledged discovery

Proposed optional S.meta.hall version 1 contains backfill policy 1, historical IDs, discovered IDs and a claim map. There are at most 30 recognized IDs across each evidence map and one recognized set claim. Preserve unknown keys and fields without counting them. No installation UUID, signatures, server verification, cryptographic ownership history or event journal is required.

At the first enabled load under the existing exclusive writer, capture the raw persisted imi-ops-v1 looks map and valid explicit crew look IDs before ensureCrew can add or repair anything. Historical IDs are known IDs whose saved bit is exactly 1 or true, plus known IDs explicitly present on persisted owned desks' crew. Do not infer old purchases, dates, rarity roll history, prices, prev looks, screenshots, hats or deleted crew. Saved bits can include migrated or undone looks, and can have been edited by a player. This policy accepts local historical observation, not acquisition provenance or tamper resistance. A prior reset may already have lost looks; lost history cannot be reconstructed. Saved nonstandard values remain preserved and excluded pending owner disposition.

Persist the historical snapshot and initialized Hall namespace together before publishing historical progress or enabling Claim. Failure keeps the captured snapshot for exact same-process Retry and holds normal writers/resets through existing reward ownership. No token is granted by initialization. First-load historical completion is eligible for this new Hall set reward under the proposed policy, unlike LG-01's existing-award L/C/G waiver. This is an explicit new owner decision, not a silent extension of that approval.

For later discovery, Save discoveries freezes a deduplicated union of validated current S.looks bits and actual current owned-desk crew IDs. Stage the union into S.meta.hall.discovered on a detached full-state candidate and persist through Economy.saveStateAcknowledged under the existing writer. Publish Hall metadata only on success. Label unsaved live differences "Discoveries waiting to save" and do not use them for set completion. This acknowledges observation and saves the accompanying room state; it does not certify that a prior hire price was durably paid. A look rolled and undone still counts if its existing seen bit survives. A look lost before this save is not guaranteed to count.

This explicit action is the smallest faithful stage. It avoids rewriting every hire/reroll/reset owner. No automatic discovery from render, celebration, sold event or acquisition event. Periodic saves may persist legacy S.looks without making it Hall evidence; the next explicit discovery action can acknowledge it. After initialization, do not call later bits historical. No new RNG call, odds change, paid draw or acquisition button is permitted. Existing random acquisition is disclosed, not claimed to be a guaranteed completion route.

Ordinary Printing, challenge entry/exit, Imprint and Estate retain Hall evidence, claim receipts and stored tokens. Pending volatile Hall actions block reset until Retry or reload resolves them. Full local erase may clear Hall with the existing timeline; it is not paid restoration. Older builds that ignore the gate are outside the guarantee. Add Hall cold recognition to VaultSaveGate: a present Hall namespace requires lg09hall=1 and lg01a=1; missing flags, unknown version or inconsistent claim/token data preserve storage and block writing before boot. An absent namespace stays absent with Hall off. Supported records merge unknown fields. Unsupported records are held, never normalized away.
