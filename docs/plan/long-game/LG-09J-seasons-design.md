## Calendar and quiet participation

Anchor A = Date.UTC(2026,0,5), Monday 2026-01-05 00:00:00 UTC, milliseconds 1767571200000. W = 604800000 milliseconds. For a finite nonnegative safe millisecond observation t >= A, weekIndex = floor((t-A)/W); start = A+weekIndex*W; end = start+W. Theme index = weekIndex modulo 2. Intervals are [start,end); exact end belongs to the next week. Dates before A or arithmetic outside safe integers refuse participation and preserve state. UTC governs identity everywhere; local formatting may accompany an explicit UTC end date. Daylight saving and premium speed never change boundaries. No ISO week-number/year ambiguity.

Example: 2026-10-12 00:00 UTC is weekIndex40, Typewriter week; 2026-10-19 is index41, Word-bank week. Whole skipped intervals require O(1) arithmetic, no iteration, catch-up rewards or missed-week entries.

Show objective, current preview amount and end timestamp before participation, with "Review free week", then "Participate free" and "Cancel". The review binds weekIndex, theme, rule and exact reward descriptor. A changed week or rate requires a fresh review. Participation atomically acknowledges that descriptor, current selected metric baseline and start observation before publishing active state. No historical delta or retroactive enrollment. Use current cumulative counter, not wallet, stock or rendered text. Counters must be finite nonnegative safe integers. Target is a difference comparison; reject unsafe target arithmetic.

Active controls are "Save progress" and "Leave week free". Saved progress is capped at target. Optionally show a live unsaved estimate clearly labelled "Not saved"; it cannot mark Complete or pay. Simpler initial UI may show saved progress only. Save progress below target persists the latest observation; at target it creates a completed proof and consumes this week's one success. Copy then reads "Complete. Your saved bonus has no expiry" and "Claim N bananas". Claim is separate from completion. No automatic enrollment or award detection by presentation events.

No urgency colors, ticker, badge, notifications, countdown animation, streak, paid extension, last-chance language or login punishment. Disclosure: "Optional ordinary bonus. Skipping is free. Themes return. Save progress before the UTC end. Saved completed bonuses never expire. This device uses its local clock." Ordinary progression always remains available unless an existing acknowledged transaction requires the shared save hold.

## Proof and eligibility

Ops press increments stats.letters once per press and stats.manual only for non-auto; generated lucky/golden extras are not additional increments there. simulateAway increments stats.letters in its own aggregate path. keeperBulk increments stats.words; bankWord increments it after consuming actual letters. Use those existing counters as their defined units, without claiming equal raw-letter accounting across online and away paths. Seasons does not rewrite them.

A visible, current owner command freezes one stat sample, its local acceptedAt, baseline, week, sequence, source identity and descriptor. An acknowledged prepare contains the sample; acknowledged finish publishes saved progress or complete. For a timely sample require participationAt <= acceptedAt < end and acceptedAt >= previous saved observation time. The sample must be >= baseline and >= last saved sample. Unsupported/regressing stats hold for repair; never clamp a negative difference to fabricate progress or silently reset baseline. A completion proof states observedAt, metric, baseline, sample, delta and rule. It proves that this cumulative increase was observed by a command before expiry. It does not prove individual production timestamps, genre, weather, book ownership or paid acquisition.

Away production counts only if the player returns, settles the existing away owner and issues Save progress before end. Closed-tab, hidden-tab or hosted minigame time does not itself save completion. If the first later observation is at or after end, expire the unfinished attempt even if the counter is now high enough. No undated later delta can establish pre-expiry completion. Stock at Start can help later production, but initial stock itself is not evidence. Auto/manual/keeper/bulk work may raise these stats; sales, authored/generated/kid/library identity, Publisher, Folio, Works, media and minigame scores do not independently qualify. Challenge/A11 production counts only insofar as the same cumulative counters actually rise; no challenge clear or sale-event inference. Garden/reward letter grants do not directly increment typed/word counters; later real banking can count toward Word-bank week. Seasons pays C only, so its reward never increments either objective. No sale rewrite or acquisition campaign is needed.

The missing seam is a named acknowledged stat-observation command and Seasons payment owner. Existing IMI tap/bank/sold/letters events and UI values are insufficient. Explicit Save progress lets us avoid modifying every press, sale or autosave route. No automatic pre-expiry completion is promised, and the UI must disclose that choice before participation.

## Reward descriptor and exact math

Propose existing bronze C formula only, assigned once per successful week. The formula is already approved for LG01 bronze cash and accepted board use; assigning it to Seasons remains UNAPPROVED. Amount = Economy.round(max(6250,min(250000,300*R))), R = rewardBasis().bananas in actual bananas per real second. Economy.scale=25; cash(250)=6250, cash(10000)=250000; round(x)=Math.round(x/25)*25. Positive half-ties round upward. There is no second floor operation. Clamp before nearest25 rounding; both endpoints are multiples25.

Ops rewardBasis supplies (royBase()+divBase())*speed(). It includes the current sustained royalty/division factors in those owners, including applicable accepted royalties changes and awards/Legacy/Muses. It excludes temporary passive rush/Critic multipliers because it uses base rates. Speed is included exactly once. Offline efficiency/cap do not reduce this online-capacity quote. Current weather is not a Seasons bonus. R=0 pays6250, R=100 pays30000, R=122.41666666666667 pays36725, R=1000 pays250000. R=100.04 pays30000, R=100.05 pays30025. A rate20.833333333333332 reaches the lower boundary; 833.3333333333334 reaches the upper boundary.

Preview is not reserved. Revalidate review before accepting participation. Freeze descriptor version1/rule1/origin seasons/kind C/tier0, rate, speed, minutes5, floor6250, cap250000 and integer amount. Retain it through progress, completion, rollover, reset and Claim. Later rate changes never resample it. No higher reward for longer sessions, no weather/speed mutation, no RNG reward, letters/token/DB/permanentstat/automation/entitlement. Existing68 awards/+1%/109DB, firsts/daily/board/Hall stay unchanged. Ordinary production/sales pay through their current owners separately; Seasons never repeats their pay or invokes a sale.

Claim adds the frozen amount to the CURRENT room wallet and CURRENT run.earned exactly once, following the accepted board-claim accounting model. It is ordinary earnings and can affect existing wallet awards/Printing naturally. It does not alter stats.lump, royTotal, divTotal, soldCount, typed, words or other sale/pickup totals; no multiplier is applied again. The reward watcher excludes event.reward, so the successor owner explicitly increments run.earned by pay once and advances its existing wallet head. Never restore the room/run from participation or completion. Reset before Claim therefore receives the same fixed bonus in the new room. This is an explicit proposed balance property, not proof of pacing.

## Time, rollover, held state and reset

For Seasons use max(Date.now(), saved lastObservedAt), with nonnegative safe integer validation. Persist the maximum in each acknowledged Seasons command, including progress, expiry and Claim. Do not persist from render or run a background scheduler. An in-document maximum may retain observed forward time before the next save; disclose that unsaved observations disappear on process loss. This is a local clock guard, not trusted time, anti-cheat or a cross-device promise. Clock rollback cannot reopen an acknowledged earlier week; a forward jump may close an unfinished week and delays access until the local calendar catches up. Clock correction never erases completed proof. Export/import/edited storage/clock changes while closed remain limitations.

Unfinished at end: close as expired at the next settled command/participation attempt. No payout, debt or backlog. Free Leave can be followed by fresh participation in the same week with a fresh baseline and review, unless already successful that week. No streak or loss of ordinary stock/currency. Same-week restart does not bank partial progress. HighestSuccessWeek is set at acknowledged completion, not Claim. WeekIndex <= highestSuccessWeek cannot succeed again.

Complete at rollover: retain the single completed reward indefinitely. Claim before participating again. The card prioritizes the saved reward, with current theme text secondary. After Claim, offer only the current eligible week, never intermediate missed weeks. A player can Claim a prior completion and complete the current week if they participate in time. Maximum retained payable completion is one. No expiry, replacement, forfeiture button or accumulation of missed weeks. A pending current week never replaces this slot.

Held command: the clock continues. A sample frozen strictly before end may finish exact Retry later, including a durable prepare reloaded after end. Retry never resamples stats, time or reward; no new completion is inferred. If initial prepare failed, sample remains volatile and only the live exact Retry may recover it. A close/crash before any acknowledged intent loses that sample; on reload an undated counter increase cannot recover the finish. Never show it as saved. An unacknowledged Participate that first settles after end closes unfinished without progress or payout. Retry of expiry cannot erase a previously completed proof. Pending payments resolve before any rollover cleanup.

Hidden/closed/hosted/offline intervals consume wall time. New commands require visible main-game ownership, settled away work, no hosted session/modal/tutorial and shared progression permission. No hidden callbacks manufacture samples. Reload resumes saved active state, or exact pending recovery first; then computes current interval. Completed rewards remain valid regardless of current week.

Ordinary Printing, challenge entry/exit, Imprint and Estate retain Seasons metadata, metric baseline/counters, frozen descriptor and completed/pending proof. Existing legacy doPrint retains old.meta/stats; Layers projectRoom copies the source and overwrites room fields; Estate uses that retained room projection. No epoch-bound attempt or reset adapter is proposed. A pending Seasons transaction must block all competing writers/resets using the shared guard before they project state. Post-reset Claim uses the live current room, not a historical projection. Explicit full local wipe follows existing wipe restrictions and timeline semantics; no paid restoration policy change or independent deletion path.

## Bounded optional record and acknowledged delivery

Proposed meta.seasons version1, rule1, access, sequence, lastObservedAt, highestSuccessWeek nullable, active nullable, lastOutcome nullable, lastClaim nullable, pending nullable. Active has immutable id seasons:<sequence>, weekIndex/theme/start/end/participationAt, metric/target/baseline/lastSample/savedProgress/observedAt, descriptor and status active|complete with optional completion proof. Retain only the latest outcome and latest claim. No map keyed by every week. Sequence and wallet sequence are safe integers; overflow refuses before mutation, no wrap. LastClaim remains until replaced by another acknowledged claim, preserving the current wallet-head source. Completion high-water mark plus active identity prevents replay after receipt pruning. Never prune a receipt referenced by the current wallet marker/head or pending command.

Unknown fields survive copies. Absent Seasons stays absent and default inert. Unknown version/rule/theme, invalid arithmetic, missing/orphan/inconsistent receipt, future shape or regression refuses with raw-save preservation. No repair initialization of an unsupported record. Before any runtime/welcomeBack/autosave/wallet writer, VaultSaveGate recognizes Seasons envelope, required flags and pending/receipt ownership. Rewards validation checks the module record and seasons-claim walletHead linkage. Disabled builds must not silently normalize or overwrite saved Seasons. Early pending protects writers even when module flags are missing. Recognition must cover completed/lastClaim sources as well as pending to avoid forgetting a paid source.

Use the accepted Rewards transaction/wallet bridge, adding named seasonsAction and narrowly owned Ops freeze/pending/commit methods. Commands participate, observe, leave, expire and claim; no external caller-supplied amounts, samples or timestamps. Ops captures these from the current source. Commands bind expected active/week/sequence/source; stale commands refuse before mutation. Existing identity/settlement guards still apply. Validation uses preserved source bytes/state identity, not a presentation event.

Nonmonetary command: clone source, acknowledge prepared intent with immutable sample/descriptor/acceptedAt, then acknowledge exact successor before publishing progress/complete. An implementation may atomically save the complete nonmonetary successor if it preserves the same failure/Retry contract. It cannot require a generic transaction framework.

Claim: settle current ordinary/Archive/away owners; acknowledge current wallet baseline; freeze id seasons-claim:<active.sequence>, previous wallet sequence/next sequence, marker, balance, current run.earned source, pay and descriptor. Acknowledge prepare. Credit through existing bananas.creditReward with id/previous/sequence/amount. Existing matching acknowledged marker means already paid; mismatched marker/balance holds, never pay again. Save successor containing lastClaim+walletHead, current run.earned+pay once, highestSuccessWeek unchanged, claimed outcome, active cleared, pending cleared. Publish only after acknowledged successor. If payment succeeded and successor failed, hold progression/reset and Retry only successor; matching marker prevents duplicate credit. No Core changes or new credit authority. Reconciliation must retain the last source until its marker is superseded under the existing bridge. No universal old-sale migration.
