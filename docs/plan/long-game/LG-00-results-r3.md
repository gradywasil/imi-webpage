## Conserved budget and rounding rule

The original offline batch count remains `max(1, min(300, ceil(countedRealSeconds / 20)))`. Each original batch has the same duration and original rounding operators. Only a non-default-speed Deadline run creates budget records. Sale/deadline boundaries release parts of those records; they do not create new allowances.

At the first prefix of each original batch and desk, sample the actual typist rate, restoration, training, efficiency and real midpoint sky. Store the full unrounded typed expectation and its one `Math.round` allowance. Before the original batch end, release the lesser of that allowance and `floor(unroundedExpectation * elapsedFraction)`, cumulatively. At the original end, release the remainder of the original rounded allowance. This prevents a rounded-up future letter from appearing early and retains a rounded-down original endpoint. No remainder is lost between inserted boundaries.

Sample `offlineDist` once per original batch/desk with positive production. For each letter retain the existing independent draw, `floor(typedAllowance * probability) + Bernoulli(fractionalPart)`. Do not normalize its sum to the typed count; the original algorithm can produce more or fewer inventory letters than the typed statistic. Release each integer inventory allowance cumulatively in proportion to already-issued typed letters using a floor. This does not add RNG calls per prefix or expose inventory tied to unissued typing. The final original batch endpoint releases its full original stochastic inventory allowance.

Grant XP once for a positive typed allowance, at the original batch end, using the original full typed allowance divided by crew count. New XP levels affect later original batches, not additional rate samples caused by a sale boundary. Weather also samples once at each original real midpoint. For a capped timed run these midpoints are in the counted interval starting at departure; the default bulk path retains its existing return-ending samples. The original midpoint sampling is still a bulk approximation, not an event-by-event weather simulation.

Keeper capacity has one original `max(2, ceil(fullBatchGameSeconds * efficiency * MuseMultiplier / keeperPeriod))` allowance. Prefixes expose only the floor of elapsed unrounded effort; minimum-two and ceil remainders become available at the original batch end. Subtract actual previously banked work from cumulative exposed capacity. Unused exposed capacity can serve ingredients that become available later within the batch but expires at its original end. The optional fourth argument to the real `keeperBulk` carries its word cursor, whether the partial pass banked anything, and its maximum twelve passes. Only the activated timed caller supplies it. Focused banking and real ingredient consumption still use the existing function. A no-progress scan can retry when later production arrives, while successful completed passes never restart.

The bounds remain the existing maximum 300 production batches, 200 publisher slots and one clamped Deadline boundary, with finite original keeper traversals. The repair introduces no per-letter production loop, substitute simulation, reset rule, price, efficiency, award, payout formula or RNG source. Sales still call the unchanged real publisher/write-title functions after the released production and banking prefix. An expiry cannot use future work; an early legitimate success survives the remainder of a long absence. Original real caps, full-away Deadline advancement, late-sale payment and pre-sale royalty basis remain intact.
